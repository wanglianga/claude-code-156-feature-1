# 县域农贸批发冷库入库质检分拣出库结算平台

面向县域农贸批发市场冷库的一体化平台，覆盖农户 / 合作社 / 批发商送货（葡萄、草莓、叶菜、鲜肉、冻品、水产）后的
**到货登记 → 质检验收 → 分拣分级 → 库位温区 → 出库发运 → 损耗报损 → 财务结算 → 监管追溯** 全流程，
把入库、质检、分拣、库位、出库、损耗和结算连成一条可追溯的**批次链**。

技术栈：Vue 3 + Vite + Element Plus + ECharts（前端） · Spring Boot 3 + Spring Data JPA + springdoc-openapi（后端） · PostgreSQL 15（数据库）。

## 一、核心能力

| 环节 | 能力 |
| --- | --- |
| 到货登记 | 货主、品类、批次、产地、毛/皮/净重、到货温度、包装、检疫证明、预计出库客户、结算方式、锁价、车牌、混批混装 |
| 质检验收 | 外观、成熟度、腐损率、含水率、复测温度、票证六项验收；结论：**准予入库 / 转分拣 / 降级入库 / 退货** |
| 温度超标处置 | 到库温度超合同要求时，质检员登记**温度、到货时间、车厢照片、抽检腐损率**；货主确认**降级入库 / 现场退货 / 预冷后复检**（影响保鲜期、仓储费、售价）；预冷复检前**冻结批次销售**，平台安排**复检时段与暂存温区**；复检不合格**自动撤回已分配出库计划**，销售员**替代批次重排并向客户说明到货差异**；投诉时平台**回看超标与货主确认记录**给出责任建议 |
| 分拣处理 | 按 A 级 / B 级 / 加工级称重定价，决定保鲜温区与售价；分拣工时、损耗率自动核算；货主损耗争议可挂账并由管理端裁定 |
| 库位温区 | 冰温保鲜区 / 冷藏区 / 冷冻区，库位容量与占用实时更新；上架、转仓、报损；**温区故障后只出不进**并自动告警 |
| 出库调度 | 排单与执行出库；支持临时改客户、客户优先（催货）、客户锁价自动取价与履约量核减；出库即扣可售重量并释放库位；冻结批次禁止排单/出库；已撤回计划支持替代排单 |
| 损耗结算 | 冷库责任报损按货位价补偿货主；分拣争议冷库承担差额入账单；货主"按原重结算"时全部非退货损耗由冷库补偿 |
| 客户投诉 | 出库后坏果/短重/温度投诉回挂批次链，责任裁定（货主/冷库/承运/客户）与赔付自动进入账单；裁定前可查看**温度超标处置与货主确认证据链** |
| 财务账单 | 按实际可售重量、等级价、仓储费（kg·天）、预冷费、分拣服务费、低温工时费、损耗补偿、投诉赔付、退货、预付款抵扣生成账单 |
| 管理看板 | 在仓停留天数、温区占用、可售重量变化、累计损耗、客户催货、风险告警；调度建议：**高风险先出 / 锁价客户先满足 / 转加工渠道** |
| 监管追溯 | 任一批次从入库到最终客户的全链时间线（含温度超标处置节点）、库存移动流水、分拣/质检/处置单/账单/投诉一屏可查 |

### 内置的经营风险场景（自动告警并串联批次链）

到货温度超标（含处置单全流程）、混批混装、临时改客户、客户要求优先出库、冷库温区故障、分拣损耗争议、
货主要求按原重结算、出库后客户投诉坏果、在仓超时高风险、锁价客户待履约、
预冷复检不合格、出库计划撤回。
任何一次降级、转仓、报损或温度超标处置都会改变该批次后续账单口径（账单可在业务变化后"重新生成"重算）。

### 到货温度超标处置流程（状态机）

```
质检员登记超标（温度/到货时间/车厢照片/抽检腐损率）
        │  处置单 PENDING（待货主决策）
        ▼
货主三选一确认（记录确认人与确认意见，作为投诉责任判定依据）
  ├─ 降级入库 DOWNGRADE → 生成降级货位批次：保鲜期缩短、售价按基准价折让、仓储费正常计
  ├─ 现场退货 RETURN    → 批次关闭退货，不产生保鲜期/仓储费/售价；已分配出库计划自动撤回
  └─ 预冷复检 PRECOOL   → 批次冻结销售（禁止排单与出库）
        │  平台安排复检时段 + 暂存温区（占用温区容量）
        ▼
      复检登记
        ├─ 合格 PASS → 解除冻结，正常质检/出库；预冷费（暂存kg×费率）入账单
        └─ 不合格 FAIL → 批次退货关闭、释放暂存与货位占用、
                         已分配客户的出库计划自动撤回（WITHDRAWN）并告警，
                         销售员选择替代批次重新排单，向客户说明到货差异
```

客户投诉坏果时，`GET /api/complaints/{id}/evidence` 回看该批次温度超标处置单与货主确认记录，
自动给出责任方建议（如：货主确认降级入库 → 建议货主责任；复检不合格批次仍流出 → 建议冷库责任）。

## 三、一键启动（Docker Compose）

前置条件：已安装 Docker 与 Docker Compose（v2）。

```bash
cd /workspace/156-feature-1-a
docker compose up -d --build
```

启动完成后：

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 前端页面 | http://localhost:8088 | nginx 托管，自动反代 API |
| 后端 API | http://localhost:8080 | 健康接口可直接访问 |
| Swagger UI | http://localhost:8088/swagger-ui/index.html | 经 nginx 反代；也可直连 8080 |
| OpenAPI 文档 | http://localhost:8088/v3/api-docs | OpenAPI 3.x JSON |

> 国内网络构建前端镜像时若 npm 官方源不可达，编辑 `docker-compose.yml`，
> 把 web 服务 build args 中的 `NPM_REGISTRY` 改为 `https://registry.npmmirror.com` 后重新构建。

停止与清理：

```bash
docker compose down          # 停止容器（保留数据卷）
docker compose down -v       # 连同数据库数据卷一起删除
```

## 四、本地开发方式

### 4.1 数据库

任选其一：

- 直接使用本机 PostgreSQL 15，创建数据库：
  ```sql
  CREATE DATABASE coldchain;
  ```
- 或仅启动 compose 中的数据库：`docker compose up -d db`

### 4.2 后端（默认端口 8080）

```bash
cd backend
mvn spring-boot:run
# 或：mvn package -DskipTests && java -jar target/cold-chain.jar
```

数据库连接通过环境变量覆盖（默认值见 `backend/src/main/resources/application.yml`）：

```bash
DB_URL=jdbc:postgresql://127.0.0.1:5432/coldchain DB_USER=postgres DB_PASSWORD=postgres mvn spring-boot:run
```

首次启动自动建表并写入种子数据（测试账号、3 个货主、4 个客户、6 大品类温度阈值与费率、
3 个温区 10 个库位、1 份葡萄锁价协议）。

### 4.3 前端（默认端口 5173，已配置 /api 代理到 8080）

```bash
cd frontend
npm install --registry=https://registry.npmmirror.com   # 如官方源慢
npm run dev
```

浏览器打开 http://localhost:5173 。

## 六、验证方式

### 6.1 自动化端到端业务链（已实际执行）

后端启动后，另开终端：

```bash
cd backend
python3 e2e_test.py
```

脚本会自动完成并逐接口断言（注意：脚本面向**全新种子库**设计，重复执行前请重置数据库
`docker compose down -v && docker compose up -d --build`，否则种子锁价额度等状态会影响断言）：

1. 管理员登录；
2. 登记 3 个到货批次：葡萄 1000kg（**到货温度 12℃ 超标 + 混批混装**）、草莓 300kg（正常）、叶菜 200kg；
3. 质检：葡萄转分拣、草莓直接入库（核定损耗 2%）、叶菜整批退货（退货批次禁止生成账单，已断言 400）；
4. 葡萄分拣 A600/B330/加工20 = 950kg，损耗 50kg（5%），工时 90 分钟，**货主争议 → 裁定冷库承担 20kg**；
5. 全部上架到冰温库；货主预付款放款 2000 元；
6. 锁价客户优先出库 A 级 500kg（断言命中锁价 11.5 元）；**临时改客户**出库 B 级 300kg；
7. 出库后投诉坏果 → 裁定货主责任赔付 300 元；
8. 温区故障上报 → 故障温区**禁止上架（断言 400）**→ 余货转仓 → 修复温区；
9. 加工级 20kg 冷库责任报损；
10. 生成账单并确认、结算：
    销售收入 8150 元 + 冷库损耗补偿 268.4 元 − 仓储费 332.5 − 分拣费 570 − 工时费 54
    − 投诉赔付 300 − 预付款抵扣 2000 = **应付货主 5161.9 元**；
11. 追溯链断言包含 ARRIVAL/INSPECTION/SORTING/PUT_IN/OUTBOUND/COMPLAINT/SETTLEMENT 全部节点（共 16 个），
    最终客户流向 2 条；
12. 管理看板总览、在仓监控、调度建议（紧急出库 / 锁价履约）、温区占用、未处理告警全部返回；
13. **温度超标·预冷复检不合格链**：草莓 500kg 到库 8℃（合同 0~4℃）→ 质检员登记超标（温度/到货时间/车厢照片 2 张/抽检腐损 6%）→
    重复登记与未超标登记均断言 400 → 质检入库并给喜连连排单 200kg → 货主确认**预冷后复检**（批次冻结，
    断言新排单 400、已排单执行 400）→ 平台安排复检时段与暂存温区（断言温区占用 +490kg）→
    复检 6.5℃ 仍**不合格**：批次退货关闭、出库计划**自动撤回**（WITHDRAWN）、温区占用释放、
    RECHECK_FAILED 与 PLAN_WITHDRAWN 告警产生 → 销售员以另一合格草莓批次**替代排单**（断言 replacesOrderId
    与到货差异说明）并执行出库 → 追溯链含 TEMP_HANDLING 节点；
14. **温度超标·降级入库链**：草莓 300kg 到库 9℃ → 货主确认降级 B 级、折让 20%、保鲜期 2 天
    （断言货位价 15×0.8=12 元/kg、保鲜期 2 天）→ 出库 100kg 给客户 → 客户投诉坏果，
    `GET /api/complaints/{id}/evidence` **回看超标与货主确认记录**，断言平台建议**货主责任** →
    裁定赔付 120 元 → 账单含销售收入 1200 与投诉扣款 −120，且无预冷费；
15. **温度超标·预冷复检合格链**：草莓 200kg 到库 7℃ → 预冷复检合格（断言解除冻结）→
    正常质检入库出库 → 账单断言**预冷费 −60 元**（200kg × 0.3 元/kg）；
16. **温度超标·现场退货链**：草莓 100kg 到库 10℃ → 货主确认现场退货（批次关闭、退货 100kg），
    退货批次生成账单断言 400；
17. 无超标记录批次的投诉证据断言建议"待裁定"（PENDING）。

最近一次实际执行结果：**全部接口断言通过（`全部业务链验证通过 ✅`）**。

### 6.2 手动验证建议路径

1. 用 `admin` 登录，查看管理看板的告警铃铛与调度建议；
2. 「到货登记」录入一车货（可故意把温度填超阈值），观察自动告警；
3. 「温度超标处置」对超标批次登记处置单（温度/到货时间/车厢照片/抽检腐损率）：
   - 选择**预冷后复检** → 批次列表出现"冻结"标记，出库调度无法对该批次排单；
     回到本页**安排复检**（选复检时段与暂存温区）→ **复检登记**填不合格，
     观察批次退货关闭、该批次已排单的出库计划变为"已撤回"；
     到「出库调度-已撤回」页签点**替代排单**，选择替代批次并填写到货差异说明；
   - 或选择**降级入库**（填折让率与保鲜期）→ 库位温区上架后按折让价销售；
   - 或选择**现场退货** → 批次直接关闭；
4. 「质检验收」选择待检批次给出结论；
5. 「分拣处理」提交分级结果，勾选货主争议，再在同页裁定；
6. 「库位温区」上架、把冰温库置为故障、对余货转仓、报损；
7. 「出库调度」排单（选择与计划客户不同的客户触发临时改客户告警、勾选优先），执行出库；
8. 对已出库单登记投诉，在「客户投诉」页点**裁定**：弹窗内自动展示该批次的
   温度超标处置与货主确认记录，并给出责任方建议（可一键采用）；
9. 「财务结算」选批次 → 生成账单 → 确认 → 结算付款（预冷复检批次可见"预冷费"明细）；
10. 「监管追溯」选批次查看从入库到最终客户的完整流向（含温度超标处置节点）；
11. 打开 Swagger UI（http://localhost:8080/swagger-ui/index.html）可查看并调试全部 OpenAPI 3.x 接口
    （"温度超标处置"分组：登记/决策/安排复检/复检/查询，出库分组含替代排单，投诉分组含责任证据）。

## 七、账单口径说明（实现细节）

- 销售收入：按已出库明细实际计价（手工单价 > 客户锁价 > 货位批次分拣定价）；
- 仓储费：每个货位批次按「重量 × 在仓天数 × 品类仓储费率」，出库/报损事件自动截断天数，不足 1 天按 1 天；
- 预冷费：温度超标选择预冷复检的批次，复检完成时按「暂存重量 × 预冷费率（默认 0.3 元/kg，
  `app.precool.fee-per-kg` 可配）」一次性计收，复检合格与否均计入账单；
- 分拣费：分拣产出重量 × 品类分拣费率；低温仓工时费：工时分钟 × 0.6 元；
- 损耗：货主责任损耗不计价；冷库责任报损与分拣争议冷库承担差额按货位均价补偿；
  勾选"按原重结算"时，除退货外全部损耗由冷库按均价补偿货主；
- 投诉：货主责任赔付从货款扣除；冷库责任由冷库直接对客赔付（不扣货主，仅在账单备注）；
- 预付款：放款增加货主应收余额，账单结算时自动抵扣并回写台账流水。
